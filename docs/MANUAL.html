🤔¿Qué es API Lab?

Imaginá que querés aprender a manejar un auto. ¿Qué necesitás? Un auto para practicar. No el de tu viejo, no el de tu tía, no un auto alquilado. Uno donde podés meter la mano en el motor, chocar contra un colchón y no pasa nada.

Bueno, API Lab es tu "auto de prácticas" pero para aprender cómo funcionan las APIs.

Analogía

Una API es como un mozo en un restaurante. Vos le hacés preguntas (pedís la carta), el mozo va a la cocina, y te trae la respuesta (tu comida). Acá el "mozo" es API Lab: vive en tu computadora, le hacés preguntas por internet, y te contesta con datos.

En este caso los datos son reales y útiles:

  • 🔓 Técnicas de escalada de privilegios en Linux (para practicar pentesting)
  • 🐧 Comandos básicos de Linux (para uso diario)
  • 🐚 Reverse shells (para entender cómo se ven los "shells inversos")

Todo corre en tu propia máquina, sin internet, sin riesgo. Podés romper todo lo que quieras que no pasa nada.

📋Antes de empezar

Necesitás tener dos cosas en tu computadora:

Requisito 1

Python 3.8 o más nuevo

Para verificar si lo tenés, abrí una terminal y escribí:

python --version

Si te muestra algo como Python 3.10.0 o más alto, estás listo. Si te dice "no se reconoce", hay que instalarlo desde python.org.

Requisito 2

Un navegador

Chrome, Firefox, Edge, el que sea. Sirve cualquiera.

También vas a necesitar curl para los ejemplos de la línea de comandos. En Windows 10/11 ya viene instalado.

Ojo

No necesitás saber programar para usar API Lab. Sí ayuda tener una idea básica de cómo se abre una terminal. Si nunca la abriste, no te preocupes: el Paso 1 te enseña.

⌨️Paso a paso

1

Abrir la terminal

La "terminal" es una ventanita negra donde escribís comandos en vez de hacer click. Suena viejo, pero es la forma más rápida de hablar con tu computadora.

En Windows 10 u 11:

  1. Apretá la tecla Windows (la del logo, abajo a la izquierda)
  2. Escribí cmd o powershell
  3. Apretá Enter
  4. Listo: tenés una ventanita negra abierta
Figura 2: así se ve una terminal recién abierta en Windows.
TIP

Cuando veas C:\Users\> quiere decir "estás parado en la carpeta de tu usuario". El cursor parpadea esperando que escribas algo. Siempre que veas ese símbolo en este manual, significa "escribí esto en la terminal".

2

Ir a la carpeta del lab

Ahora hay que decirle a la terminal dónde está la carpeta del proyecto. Eso se hace con el comando cd (que significa "change directory", o sea "cambiar de carpeta").

Escribí esto y apretá Enter:

cd "<ruta-donde-clonaste>\crear-api\option2"

Si la ruta tiene espacios (como "Mis Proyectos" o "GitHub Projects"), tenés que envolverla con comillas. Si no, la terminal se confunde.

Figura 3: el cursor ahora muestra la nueva carpeta.
Cómo saber si funcionó

Si a la izquierda del cursor ves la ruta nueva, todo bien. Si te tira un error tipo "El sistema no puede encontrar la ruta especificada", es porque la carpeta no está donde pensás. Abrí el explorador de Windows, navegá hasta la carpeta, y copiá la ruta desde la barra de arriba.

3

Instalar Flask (la herramienta que hace andar el server)

Flask es como el "motor" del lab. Sin él, el archivo lab.py no funciona. Se instala con un solo comando:

pip install flask

Apretá Enter y esperá unos segundos. Vas a ver un montón de texto bajando, y al final algo como:

Successfully installed flask-3.1.3 ...
¿Qué es pip?

Es como una "tienda de aplicaciones" pero para Python. En vez de descargar cosas a mano, le decís a pip "instalame Flask" y él se encarga.

Si te dice "pip no se reconoce"

Probablemente tu Python no agregó pip al PATH. Reinstala Python desde python.org y marcá la casilla "Add Python to PATH" en la primera pantalla del instalador. Es la respuesta al 90% de los problemas de Python en Windows.

4

Arrancar el servidor

Ahora sí, la parte divertida. Escribí:

python lab.py

Si todo va bien, vas a ver un cartelito así (sin los cuadraditos raros, eso es un problema de fuentes de la terminal que no importa):

Figura 4: el banner que muestra que el server arrancó bien.
Lo importante

Si ves la línea Running on http://127.0.0.1:5050, el server está VIVO. No cierres la terminal: el server vive adentro. Si la cerrás, se apaga.

Si dice "Address already in use"

Significa que otro programa está usando el puerto 5050. Pasá un puerto distinto al final: python lab.py --port 5060 (o cualquier número entre 5000 y 9999 que tengas libre).

5

Abrir el navegador

El server está corriendo pero "adentro" de la terminal. Para hablar con él, abrí el navegador y andá a:

http://127.0.0.1:5050

Vas a ver una página con un menú y un buscador. Esa es la "puerta de entrada" al lab.

Figura 5: lo que vas a ver en el navegador.
¿Qué es 127.0.0.1?

Es la dirección de tu propia máquina. Es como decir "yo mismo". Todas las páginas que empiezan con 127.0.0.1 viven en tu computadora, no en internet. El 5050 es el "departamento" dentro de tu máquina donde está el server.

6

Cargar los datos (¡la parte más importante!)

El lab arranca con la base de datos vacía. Los datos existen en archivos JSON, pero no están "conectados" al server hasta que vos los cargues. Es como una biblioteca con libros en la bodega: hay que subirlos al estante para que la gente los pueda leer.

Hay dos formas de cargarlos:

A) Desde el navegador (más fácil)

  1. Andá a http://127.0.0.1:5050
  2. Apretá el botón "Cargar datos"
  3. Elegí el dataset (privesc o commands)
  4. Listo, ya está cargado

B) Desde la terminal con curl (más pro)

Abrí otra ventana de terminal (sin cerrar la del server) y escribí:

curl -X POST http://127.0.0.1:5050/api/v1/datasets/privesc/load

Vas a ver algo así:

{
  "loaded_at": "2026-06-17T21:35:43Z",
  "msg": "Dataset 'privesc' cargado en DB",
  "total_categories": 11,
  "total_commands": 87
}
Figura 6: el flujo de cargar un dataset.
El verbo POST

En el mundo de las APIs hay "verbos" para distintas acciones. Los más comunes son GET (pedir datos) y POST (mandar una orden, como "cargar esto"). Por eso en el comando curl va el -X POST: para decirle a curl "esto no es una consulta, es una orden".

7

Explorar y probar cosas

Ya con los datos cargados, podés probar todos los endpoints. Acá van los más útiles:

Qué haceComando
Ver qué hay cargadocurl http://127.0.0.1:5050/api/v1/datasets
Ver toda la ayudacurl http://127.0.0.1:5050/api/v1/help
Buscar comandos "suid"curl "http://127.0.0.1:5050/api/v1/commands?cat=suid"
Solo los críticoscurl "http://127.0.0.1:5050/api/v1/commands?severity=critical"
Buscar por palabracurl "http://127.0.0.1:5050/api/v1/commands?q=python"
Ver shells reversoscurl http://127.0.0.1:5050/api/v1/shells

Búsqueda globalcurl "http://127.0.0.1:5050/api/v1/search?q=kernel"
El símbolo & en URLs

Si querés combinar filtros (por ejemplo categoría y severidad), usás & entre ellos. Asegurate de envolver toda la URL con comillas para que la terminal no se confunda.

Si querés ver el catálogo completo de todos los endpoints con descripciones largas, andá a:

http://127.0.0.1:5050/api/v1/help

O en formato texto plano (ideal para leer en la terminal):

curl http://127.0.0.1:5050/api/v1/help.txt
8

Apagar el servidor (cuando termines)

Andá a la terminal donde está corriendo el server y apretá:

Ctrl + C

Eso lo apaga limpiamente. La próxima vez que quieras usarlo, repetí desde el Paso 4.

¿Y mis datos?

Cuando apagás el server, los datos cargados se borran (viven en la memoria RAM, no en el disco). Es parte de la experiencia: cada vez que arranques, arrancás desde cero. Es como un Tetris: nuevo juego, todo vacío.

🚧Si algo no anda

Los problemas más comunes y cómo resolverlos:

"python no se reconoce como comando"

Python no está instalado o no está en el PATH. Reinstala desde python.org y marcá "Add Python to PATH".

"pip no se reconoce"

Mismo problema: Python no está en el PATH. Solución: reinstalar como dijimos arriba.

"Address already in use" al arrancar

El puerto 5050 está ocupado. Probá con otro: python lab.py --port 5060

"No module named flask"

Te salteaste el Paso 3. Volvé y ejecutá pip install flask.

El navegador dice "No se puede acceder al sitio"

El server no está corriendo. Volvé al Paso 4 y verificá que la terminal diga Running on http://127.0.0.1:5050. Si no, la terminal está cerrada o se colgó.

curl dice "no se reconoce"

En Windows muy viejos curl no viene. Actualizá Windows o instalá curl desde curl.se. En Windows 10/11 ya viene.

Los caracteres chinos/rotos en el banner

Es un problema de fuentes de la terminal, no del lab. El server funciona igual. Si te molesta, abrí PowerShell con chcp 65001 antes de arrancar.

📖Glosario rápido

Palabras raras que vas a ver seguido, explicadas en castellano básico:

APIUna forma ordenada de pedirle cosas a un programa. Como un mozo en un restaurante.
EndpointUna "puerta" de la API. Cada endpoint hace una cosa distinta.
GET"Traeme datos". El verbo más común. Solo lee, no cambia nada.
POST"Hacé esto". Manda una orden al server (cargar, borrar, crear).
DELETE"Borrá esto". Como DELETE en el teclado: borra.
JSONUn formato de texto para guardar datos. Llaves { } y corchetes [ ] por todos lados.
ServerUn programa que se queda esperando que alguien le hable y le contesta.
ClienteEl programa que le habla al server. Tu navegador, por ejemplo.
curlUn programa de terminal para hacer pedidos HTTP sin abrir el navegador.
127.0.0.1"Yo mismo" en lenguaje de computadoras. Es tu propia máquina.
PuertoComo un "departamento" dentro de tu máquina. El lab vive en el 5050.
DatasetUna colección de datos. Acá hay dos: privesc y commands.
FlaskUna herramienta de Python para hacer servers web fácil.
Pentesting"Penetration testing": probar sistemas para encontrar fallas de seguridad.
Privesc"Privilege escalation": pasar de ser un usuario común a ser administrador.
Reverse shellUna conexión que hace que la máquina víctima se conecte a vos. Útil en pentesting.
